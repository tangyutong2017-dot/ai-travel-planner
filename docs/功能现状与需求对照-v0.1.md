# 功能现状与需求对照 v0.1

> 立项前的基线盘点。左边是 PRD v0.1 写下的需求，右边是**实测**出来的现状。
> 测试日期：2026-08-11 · 后端 45/45 通过（`backend/tests/smoke_test.py`）+ 前端逐屏人工验证。

## 0. 一句话结论

**骨架和外壳已经完整，大脑被摘掉了。**

创建 → 生成 → 编辑 → 输出这条主链路端到端跑得通，数据真实落 Postgres，
但"生成"环节目前产出的是占位行程——AI 生成、天气、路线三块能力尚未接入。

## 3. 实测发现的缺陷（未修，待排期）

| # | 缺陷 | 影响 | 严重度 |
|---|---|---|---|
| 1 | 创建向导 `destination` 初始值硬编码为 `"云南大理"`，视觉上像占位提示 | 用户不改就会创建一条大理行程 | 高 |
| 2 | `fill_missing_poi_data` 拿占位标题（如"围绕「自然风光」生成核心安排"）去高德搜索，匹配到随机 POI | 界面显示**假评分 4.2、假坐标** | 高 |
| 3 | 生成进度条声称"查询景点、路线与天气" | 当前根本没查，文案与实际不符 | 中（agent 落地后自动消解） |
| 4 | 工作区窄屏（< 1100px）三栏挤压 | 中间时间线被压成竖排，可读性归零 | 高（作品集截图会暴露） |
| 5 | `分享链接`、`同步日历` 按钮无 onClick | 死按钮 | 中 |
| 6 | 首页重复请求 `GET /api/trips` 2 次（dev 下 StrictMode 翻倍成 4 次） | 浪费请求 | 低 |
| 7 | `@app.on_event("startup")` 是 FastAPI 已废弃写法 | 未来版本会失效 | 低 |

## 4. 立项建议的优先级

按"作品集能不能拿得出手"排序，而非按 PRD 原序：

1. **修 #1 #2 #4** — 三个都会在演示时直接被看到，且都是小改动
2. **Generation Agent 重写** — 项目的核心价值主张，也是 P1 全部缺口的前置
3. **接 `driving_route` + `weather_for_city`** — 代码已写好，接上就能让地图和天气卡片活过来，性价比极高
4. **PDF 导出**（P0 补齐）— `window.print()` + 打印样式即可交差
5. **AI 调整输入框** — 依赖 Editing Agent，跟 #2 一起规划

## 5. 如何复现本文档的测试

```bash
# 1. 起后端（需 Postgres 在跑）
cd backend && .venv/bin/uvicorn app.main:app --reload --port 8000

# 2. 跑后端全量冒烟测试
python3 backend/tests/smoke_test.py

# 3. 起前端
cd web && npm run dev
```

**已知不足**：`smoke_test.py` 是脚本形态、依赖真实运行的服务和数据库。
后续应改造为 pytest + FastAPI `TestClient`，并用独立测试库，才能进 CI。
